# Deploying Ledger

The whole system runs on **[Render](https://render.com)**, from the `render.yaml` blueprint in this repo. Render's free tier is enough for a project demo, and it deploys straight from GitHub.

| Piece | Render service | What it is |
|---|---|---|
| Database | `ledger-db` | PostgreSQL (free) |
| API | `ledger-api` | Django + DRF behind gunicorn; also serves `/media/` photos and `/static/` admin files |
| Web app | `ledger-web` | The built React app (static files) |

## 1. First deploy (about 10 minutes)

1. Push the latest code to `main` on https://github.com/Psybah/asset-management.
2. Sign in at https://dashboard.render.com with GitHub.
3. Click **New → Blueprint**, pick the `asset-management` repository and click **Apply**. Render reads `render.yaml` and creates the database, the API and the web app.
4. It will ask for two values it can't know yet. Leave them blank for now and continue.
5. Wait for **ledger-api** to finish (the first build takes a few minutes). Copy its URL from the top of its page, e.g. `https://ledger-api.onrender.com`.
6. Open **ledger-web → Environment** and set:
   - `VITE_API_URL` = `https://ledger-api.onrender.com/api` (your API URL + `/api`)

   Save, then **Manual Deploy → Deploy latest commit** so the app is rebuilt with it.
7. Copy the web app's URL, e.g. `https://ledger-web.onrender.com`. Open **ledger-api → Environment** and set:
   - `FRONTEND_URL` = `https://ledger-web.onrender.com`

   Save; the API restarts by itself.
8. Open the web app URL and sign in with a demo account (e.g. `admin` / `admin123`).

On first start the API runs its migrations and loads the demo data. Later restarts and deploys **never** wipe data: the start command uses `seed --if-empty`.

## 2. Updating

Push to `main`. Render rebuilds and redeploys both services automatically.

## 3. Sharing it

- **App:** send `https://ledger-web.onrender.com` (your URL) to the supervisor or examiners.
- **Usability survey:** `https://ledger-web.onrender.com/survey` opens on any phone with no login, which makes it the easiest way to collect responses at Squad. Results appear on the **Usability** page (manager or admin login).
- **QR labels** printed from the deployed app open on any phone, anywhere.

## 4. Things to know about the free tier

| Limitation | Effect | Fix if it matters |
|---|---|---|
| The API sleeps after ~15 minutes idle | The first request after a pause takes ~30–60 s | Open the app a minute before a demo, or upgrade `ledger-api` to the Starter plan |
| The free database expires after 30 days | The data is deleted | Redeploy before your defence, or use a free [Neon](https://neon.tech) Postgres database and paste its URL into `DATABASE_URL` |
| No persistent disk on free web services | **Uploaded** photos disappear when the API restarts; the demo photos are restored automatically | Attach a Render Disk at `/var/data` (paid plan) and set `MEDIA_ROOT=/var/data/media` |

## 5. Environment variables

**API (`ledger-api`)**

| Variable | Value |
|---|---|
| `DATABASE_URL` | Filled in from `ledger-db` automatically |
| `SECRET_KEY` | Generated by Render |
| `DEBUG` | `false` |
| `ALLOWED_HOSTS` | `.onrender.com` (add a custom domain here, comma-separated) |
| `FRONTEND_URL` | The web app URL; allows its requests (CORS) and is encoded in server-side QR codes |
| `CORS_ALLOWED_ORIGINS` | Optional extra origins, comma-separated |
| `CSRF_TRUSTED_ORIGINS` | Default `https://*.onrender.com`; needed for the Django admin at `/admin/` |
| `MEDIA_ROOT` | Optional; where uploaded photos are stored |

**Web app (`ledger-web`)**

| Variable | Value |
|---|---|
| `VITE_API_URL` | The API URL + `/api`; read at build time, so redeploy after changing it |

## 6. Checking it works

- `https://<api>/api/survey/form/` returns JSON (this is also the health check).
- `https://<api>/admin/` shows the Django admin; sign in with `admin` / `admin123`.
- In the web app, an asset page shows its photo, and its QR code opens the same page on a phone.

## Other platforms

The same setup works anywhere that runs Python and serves static files:

- **API:** build with `pip install -r requirements.txt && python manage.py collectstatic --noinput`, then start with `python manage.py migrate && python manage.py seed --if-empty && gunicorn config.wsgi:application --bind 0.0.0.0:$PORT`. Set the environment variables above. This works on Railway, Fly.io and PythonAnywhere.
- **Web app:** build with `npm ci && npm run build` from `frontend/`, set `VITE_API_URL`, and publish `frontend/dist`. Every unknown path must fall back to `index.html`. This works on Vercel, Netlify and Cloudflare Pages.
